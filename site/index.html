挑战

让多智能体写研报，难点不在“写出来”，而在“能不能信、能不能查”

我从三个具体缺口入手，每个都对应一类可以用程序检查的约束。

数字没有出处

模型在长文里自由书写金额、比率和目标价。读者分不清哪些来自资料，哪些是计算，哪些只是顺手写出的。

角色互相锚定

辩论式流程里，后发言的角色能看到前面的评级和结论，独立判断与顺着既有观点走很难区分。

失败悄悄被吞掉

上游在结构化输出失败时会退回自由文本继续运行。出错的回答、重试和花费默认不会留下可供复核的记录。

方法

四项改造，各自落在可测试的契约上

保留上游的角色拓扑和路由，只改模型实际看到的输入、讨论方式和数字的来去。

信息流

先独立，再反证

多空研究员基于同一份资料各自写初稿，初稿封存后才看到对方并逐条回应。组合经理先在只看资料的条件下做独立初判，终判不继承前面的评级或交易员自设的门槛。

数字契约

前瞻数字由程序算

前瞻假设以结构化参数保存，由 Python 复算利润归属、每股盈利、现金桥和条件估值。终稿里的前瞻数量只能写成引用，例如 {{metric:F1:eps_per_traded_unit}}；历史数量引用证据块 {{source:E0001}}。终稿未绑定的数值先按契约定位，必要时定向修复或遮盖为待核标记，保留原句。

可重放证据

保存的 Case 可核对重放

Case 按内容寻址，保存请求、原始模型调用、失败回答和预算收据。读取时只用 Python 标准库核对输入输出绑定与计算一致，保留原始过程供复核，不需要模型、网络或第三方库。

失败处理

有界恢复，按证据决定

传输失败、长度截断、无法解析、结构不合规各有独立的证明规则和一次性额度，运行时与读回时由同一个函数判定。恢复按阶段和证据限定，v24保留非关键角色降级并增加待核交付：

  • 四类分析与交易员的全部回答被证明不可用、且重试额度已用尽时，以明示占位继续，Case 标为部分完成（PARTIAL）；预算或调用上限导致的停止仍然停止。
  • 终稿只因不超过 5 句含未绑定数字被拒时，可定向改写并整份复检；修复不可用或未通过时，v24将被拒数值遮盖为待核标记，保留原句和PARTIAL状态。

量化研究

A 股横截面量化：从数据管线到预注册的样本外评估

独立于 Agent 的研究模块。研究问题是：不同市场状态下，哪些量价路径更可能延续或反转；深度序列模型能否在人工特征和树模型之外，带来样本外增量。

  1. 数据按当时的世界构建日频原始采集后规范化存储；证券身份按日期解析，历史股票池按当时状态构建，不用今天的存续名单回填。
  2. 特征量价路径 + 市场状态个股 60 个交易日的价量路径，趋势、风险、成交活跃度与流动性代理，叠加当时的市场状态与相对强弱。
  3. 标签20 日持有收益排名下一交易日开盘到第 20 个交易日收盘的持有收益，在当日完整股票池内排名；结果未知的股票用区间表达，不静默丢弃。
  4. 切分无泄漏的时间切分日期级切分，按标签结束与可得时间清洗（purge），日期等权；预处理只在训练集上拟合。
  5. 评估保守、可复算全池 Rank IC 的保守识别区间、HAC 区间与固定市场状态分解，全部从落盘的日度指标重算。

工程

证据链上的工程约束

这些约束写在代码与测试里，发布前逐项运行。

离线 CI

离线测试

覆盖核心规则、原生集成、量化契约与隔离安装；测试步骤禁用外部网络。当前检查记录统一维护在项目状态。

JSON Schema

版本化契约

研究Case的JSON Schema按协议版本保存。已发布读者保留原报告；升级时核对已保存记录，原始文件和失败不覆盖。

0 第三方库

标准库读回

读取 Case 不导入 pydantic、openai、langgraph 或 tradingagents，测试用 python -S 验证。

追加写入

产物一次写入、不覆盖；原始发行人文件保持不变；失败回答、重试与费用收据全部保留。

私有边界

发行人文件、抽取文本、原始轨迹与人工质检只留在私有目录。公开仓库发布前扫描私有路径、密钥、长摘录与原始轨迹。

付费运行纪律

真实模型调用按任务授权并受预算与次数约束。失败先用已保存回答离线重放、归类原因，再决定修正与复测，实际用量保留。

历程

从可重放骨架到 v24

按实际提交与状态记录整理。每一步都先有可测试的契约，再接入真实模型。

  1. 08-13
    可重放骨架与契约

    任务、运行与回放接口定型：核心只暴露 run(task) 与 replay(run_ref)。

  2. 08-14
    确定性核心与人工复核闭环

    证据片段、语义与公式先过校验器，结论只能是接受、重试、弃答或人工复核之一。

  3. 09-08
    转向 TradingAgents 原生链路改造

    保留上游角色拓扑，改为结构化论点与经理逐条裁决。

  4. 09-11
    独立初判、情景隔离与前瞻复算

    组合经理先独立判断；前瞻参数交给程序计算盈利、现金与条件估值。

  5. 09-12
    有界参数修正与终稿数字绑定

    修正后复算，终稿数字只能引用有效计算或来源。

  6. 09-17 至 09-22
    A 股量化模块

    日线数据管线、证券身份修复、XGBoost 研究与固定窗口研究。

  7. 09-23
    量化信号以研究说明接入

    按日期无前视打分，渲染为确定性、可引用的研究说明。

  8. 09-25 至 09-26
    恢复策略、四类分析与资料采集

    有界的调用恢复；基本面、市场、新闻、社媒四类分析；新闻与投资者讨论的冻结采集。

  9. 09-27
    正式研报与数字契约 2

    生成常规研报版式；格式失败按证据重问；时间与来源编号写法不再误标待核。

  10. 09-28
    协议 19 与 20

    结构错误先于内容检查判定；非关键角色降级与终稿句子级数字修复。

  11. 09-30
    协议24：数值遮盖交付

    对修复不可用或未通过的终稿隐藏未绑定数值，保留原句与待核状态；遮盖后复检，不新增模型调用。

路线图

研究工作流的持续检验

从结构化输出恢复、非关键角色降级，到句子级修复与数值遮盖，按具体失败完善交付链；原始回答、修正记录和待核状态均保留。

工程约束可以复核机制，研究价值还需比较与内容验收。Quant评分已经作为来源接入；观点隔离、信号接入和数字契约不自动证明判断质量提高。

接下来

  1. 按固定资料与模型比较观点更新和报告质量。
  2. 完成量化信号接入后的固定案例配对评估。
  3. 在排序信号之上做组合层评估：换手、交易成本与回撤。
