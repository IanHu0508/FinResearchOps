挑战

AI 投研的关键：让观点、参数和证据沿同一链路更新

我将这条研究链分解为三个工程问题，分别建立输入分流、金融复算和变化留痕。

预测参数对应经营逻辑

收入、利润率、税率和利润归属共同决定盈利；股数、现金调整与估值倍数继续影响每股结果和价格。将这些关系写成参数与计算，才能解释一次修正的金融影响。

研究任务与期望答案分流

用户的问题、实质假设和风险约束进入研究，期望得到的结论单列留痕。多空先独立成稿，再回应具体反证，让观点形成与观点更新有明确顺序。

证据更新传到最终报告

资料变化、假设修改与计算结果一起保存。最终报告说明采用哪些观点、修改哪些参数，以及什么证据会再次改变判断。

方法

四项技术贡献，接通研究到交付

TradingAgents提供原生角色与路由；我围绕观点更新、金融计算、有效报告与运行恢复建立新的数据流和接口契约。

信息流

独立观点与逐条反证

我将显式用户期待与研究输入分离，让多空基于同一资料封存独立初稿，再逐条回应对方论点。组合经理用来源形成初判，后续按记录的信念处理反证；旧评级与交易员阈值在终判输入中隔离。

数字契约

经营假设到金融复算

我把收入、利润率、税率、利润归属、股数与现金调整保存为结构化参数，由Python计算盈利、EPS、现金和条件估值。修改明确记录原值、新值与依据；终稿引用有效结果，例如 {{metric:F1:eps_per_traded_unit}}；历史数量引用证据块 {{source:E0001}}。报告的数字与来源由同一引用机制连接，原参数和修改过程同时保留。

可重放证据

有效结果与研究过程双份保存

我设计内容寻址的Case记录，将请求、来源、原始回答、参数修改和有效结果一起保存。标准库读回核对绑定与计算，正式研报引用有效版本，过程记录保留完整研究路径。

失败处理

有界恢复与计算资源管理

我按角色设置推理强度，组织共享提示前缀供缓存复用，并为传输、截断、格式和内容问题设置有界恢复。运行与读回共用同一判定，v24将恢复落实到具体阶段和句子：

  • 四类分析与交易员按非关键阶段处理：额度内恢复，必要时以明示占位继续并记录PARTIAL，保留已完成的研究内容。
  • 终稿采用句子级数值修复与整份复检；修复不可用或未通过时，v24将对应数值显示为待核标记，原句和处理方式逐项留痕。

量化研究

A 股横截面量化：从数据管线到预注册的样本外评估

我构建独立于Agent的量化研究模块，比较价量路径在不同市场状态下的排序表现，并用固定评价期检验序列模型相对人工特征和树模型的增量。

  1. 数据按当时的世界构建日频原始采集后规范化存储；证券身份按日期解析，历史股票池按当时状态构建，不用今天的存续名单回填。
  2. 特征量价路径 + 市场状态个股 60 个交易日的价量路径，趋势、风险、成交活跃度与流动性代理，叠加当时的市场状态与相对强弱。
  3. 标签20 日持有收益排名下一交易日开盘到第 20 个交易日收盘的持有收益，在当日完整股票池内排名；结果未知的股票用区间表达，不静默丢弃。
  4. 切分无泄漏的时间切分日期级切分，按标签结束与可得时间清洗（purge），日期等权；预处理只在训练集上拟合。
  5. 评估保守、可复算全池 Rank IC 的保守识别区间、HAC 区间与固定市场状态分解，全部从落盘的日度指标重算。

工程

支撑研究链路的工程实现

我将模型调用、确定性计算和交付管理分层实现，通过离线测试与发布流程核对各层接口。

离线 CI

离线测试

覆盖核心规则、原生集成、量化契约与隔离安装；测试步骤禁用外部网络。当前检查记录统一维护在项目状态。

JSON Schema

版本化契约

研究Case的JSON Schema按协议版本保存。已发布读者保留原报告；升级时核对已保存记录，原始文件和失败不覆盖。

0 第三方库

标准库读回

读取 Case 不导入 pydantic、openai、langgraph 或 tradingagents，测试用 python -S 验证。

追加写入

产物一次写入、不覆盖；原始发行人文件保持不变；失败回答、重试与费用收据全部保留。

私有边界

发行人文件、抽取文本、原始轨迹与人工质检只留在私有目录。公开仓库发布前扫描私有路径、密钥、长摘录与原始轨迹。

付费运行纪律

真实模型调用按任务授权并受预算与次数约束。失败先用已保存回答离线重放、归类原因，再决定修正与复测，实际用量保留。

历程

从可重放骨架到 v24

按实际提交与状态记录整理。每一步都先有可测试的契约，再接入真实模型。

  1. 08-13
    可重放骨架与契约

    任务、运行与回放接口定型：核心只暴露 run(task) 与 replay(run_ref)。

  2. 08-14
    确定性核心与人工复核闭环

    证据片段、语义与公式先过校验器，结论只能是接受、重试、弃答或人工复核之一。

  3. 09-08
    转向 TradingAgents 原生链路改造

    保留上游角色拓扑，改为结构化论点与经理逐条裁决。

  4. 09-11
    独立初判、情景隔离与前瞻复算

    组合经理先独立判断；前瞻参数交给程序计算盈利、现金与条件估值。

  5. 09-12
    有界参数修正与终稿数字绑定

    修正后复算，终稿数字只能引用有效计算或来源。

  6. 09-17 至 09-22
    A 股量化模块

    日线数据管线、证券身份修复、XGBoost 研究与固定窗口研究。

  7. 09-23
    量化信号以研究说明接入

    按日期无前视打分，渲染为确定性、可引用的研究说明。

  8. 09-25 至 09-26
    恢复策略、四类分析与资料采集

    有界的调用恢复；基本面、市场、新闻、社媒四类分析；新闻与投资者讨论的冻结采集。

  9. 09-27
    正式研报与数字契约 2

    生成常规研报版式；格式失败按证据重问；时间与来源编号写法不再误标待核。

  10. 09-28
    协议 19 与 20

    结构错误先于内容检查判定；非关键角色降级与终稿句子级数字修复。

  11. 09-30
    协议24：数值遮盖交付

    对修复不可用或未通过的终稿隐藏未绑定数值，保留原句与待核状态；遮盖后复检，不新增模型调用。
