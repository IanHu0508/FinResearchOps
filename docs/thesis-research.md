# 投研观点与反证更新

当前状态、运行证据与限制见 [status](status.md)。本页说明机制和操作。

`research-thesis` 是轻量化主入口，不要求财报审核任务、证券审核包或有限
论点目录作为前置。上游提供原生图、路由、工具和经理报告渲染；本项目修改
模型实际输入与讨论方式。这是原生链路改造，不是原封不动的基线。

## 研究问题、假设与用户期待

`--question`是研究问题；可重复的`--hypothesis`保留需要检验的实质论据，
`--research-constraint`保留期限、风险关注等研究约束。模型仍须核对这些假设，
不能将它们当成已经披露的事实。`--user-view`只记录用户期待的结论，保存在Case和
报告中，不进入任何主研究请求；后置复核因为读取完整报告而可见它。

例如，把“我看多，因为海外收入可能加速”拆为研究问题“检验海外收入加速及其
盈利和估值影响”、假设“海外新产品可能推动收入加速”、用户期待“我看多”。
拆分由调用者明确完成，不新增模型分类器，也不自动删改原有自由文本。
若倾向仍混在`--question`或假设理由中，程序不会声称已经自动去除。
这项隔离不识别训练偏好，不消除模型自身先验，也不删除有意义的多空论据。

## 信息如何传递

| 阶段 | 读取 | 产出 |
|---|---|---|
| 基本面、市场入口 | 实时模式使用原生工具；冻结模式直接载入 | 完整原始资料；不把生成笔记传给研究角色 |
| 多空首轮 | 相同完整原始资料；各自看不到对方初稿 | 成立或失败条件、金融机制、证伪观察 |
| 多空第二轮 | 自己初稿和对方封存初稿 | 逐条更新自己、逐条回应对方 |
| 研究经理 | 原始资料与更新论点 | 逐项评估、研究计划、估值依据与缺口 |
| 交易员 | 同样资料与研究计划 | 独立提案供人查看，不把自设门槛传给最终判断 |
| 风险角色 | 同样资料与更新论点；无其他风险角色先行意见 | 独立分析机会成本、下行风险和情景权衡 |
| 组合经理：独立初判 | research资料与实际提供的组合信息；不读同伴观点或声明的情景 | 独立评级、估值依据摘要与2至4条决定判断的信念 |
| 组合经理：前瞻提案与复算 | 研究资料、更新论点及风险分析；不读独立初判或声明情景 | 提出经营驱动及年度预测参数，程序复算归母盈利/EPS、现金代理、条件价格与回报 |
| 组合经理：反证更新 | 研究资料、独立信念、研究分析、本轮前瞻提案及复算结果；无初判评级、摘要和预设触发字段 | 评估每条预测路径，更新信念，解释盈利现金与价格回报怎样支撑或不足以支撑评级 |
| 轻量资料复核 | 已保存的完整报告文本及原始资料 | 独立疑点清单，区分草稿问题与最终判断问题，不改写主报告 |

冻结模式跳过重复的模型资料整理调用。实时工具阶段的生成笔记只保留在轨迹中，
避免把其中已有倾向的解释当成中立事实传入研究。第二轮后执行的一方不读取先执行方的修改稿。最终经理输入不含研究经理的
评级、交易员的买卖方向或其自设门槛。其他角色提出的观察阈值也只是研究假设，
不是用户硬约束；尚未披露的未来数据不能当作未达标的负面证据。`Hold` 表示模型形成的中性观点，`REVIEW` 表示
依据不足以评级。无持仓数据时不能把未知当作零仓位；这里没有交易执行。

组合经理的三步在同一个原生节点内执行。独立初判是“有资料、未读同伴”的
判断，不是对训练先验的直接测量。终判不读取初判评级/摘要/整份财务草稿，也不继承独立信念、研究者或风险角色的预设触发字段；只传入待核对的信念与分析。初判不再重复生成完整财务报告。反证后可以修改也可以维持；程序事后计算评级变化，只检查
信念覆盖、实际输入和评级变化记录一致，不判断哪种评级正确。报告区分
这两个时刻以及早期研究经理/交易员的过程输出，不把过程评级当另一份最终结论。

前瞻草稿允许有理由的研究假设，逐项保存数值、模型标注的依据类型、理由与引用。
程序计算先于终判，覆盖收入与利润率、非经营损益、税费、非控股归属、普通股/ADS、
汇率和净利润至经营现金流的调节；现金资本购买只扣一次。条件价格使用年度归母
盈利与明确倍数，不重复加净现金。估值日按研究期限确定，区分估值日滚动年度、
之后年度和指定财年盈利分母；没有正持有期、报价日期或必要输入时不伪造累计回报。
缺股息保留不含股息回报，不自动把未知股息改成零。

少数股东归属分别记录经济性质（盈利、亏损或未知）与非负绝对金额，由程序确定
盈利扣减或亏损加回的方向；报表扣减行的括号不能直接理解为经济亏损。经营现金
流从合并净利润起算，分为非营运资金调节与经营性资产负债现金影响；CFO减净利润
是两组的合计，不能拿该差额当第一组后再重复加第二组。经营性资产负债的现金影响
也不是简单资产负债表余额变动，或严格估值口径的净营运资本。来源类型与经济性质
仍由模型提出，不因结构完整而自动成为已验证事实。

退出倍数缺乏依据时，程序仍可计算“起点价格÷情景年度EPS”及有股息假设时的
含息打平倍数，帮助解释盈利变化怎样影响价格要求。这些是条件等式，不是合理
倍数或市场共识；不代填退出倍数、目标价或期望收益。错位历史TTM与未来年度的
比较应称相对历史参考期的条件增幅，列出日期与季节衔接限制，不能冒称同比。

最终经理可以采用、有条件采用或拒绝每条路径。算术结果、模型自述的来源分类及
引用存在均不认证预测或估值。没有可辩护倍数时仍交付盈利现金预测和争议；REVIEW
不阻断完整研报。这个数量化片段只覆盖普通非金融经营公司的年度盈利法，不强套
银行、地产或早期亏损公司，也不接入 Daily Investment。当前和历史运行状态只见
[status](status.md)。

这些边界阻断特定输入传递途径，不能消除模型训练偏好、资料选择偏差、
问题措辞影响，或自由文本里的残余倾向。反证回应也可能流于形式，应检查
理由是否实质改变现金流、风险、估值假设或结论。引用存在不证明论断正确。

## 运行

使用已经配置好 TradingAgents 的集成 Python。路径须为本机私有目录中的
绝对路径；密钥只从本机配置读取，不写入报告或模型输入。

```bash
PYTHONPATH=src <integration-python> -m finauditgate.cli \
  --artifact-root <absolute-private-run-directory> research-thesis \
  --symbol <TICKER> --as-of <YYYY-MM-DD> \
  --question '经营质量、当前价格吸引力和关键失效条件是什么？' \
  --env-file <absolute-private-model-config> \
  --model deepseek-flash --reasoning-effort max \
  --max-output-tokens 65536 --max-spend-cny unlimited
```

默认使用原生供应商工具。加入 `--sources <absolute-private-bundle.json>` 改用
冻结资料，不发起新行情查询。`--no-review` 跳过报告之后的复核 Agent，
主体研究算法相同。金额上限可设置数值；调用次数、长度和超时限制保留。
费用估算基于配置费率，不是供应商账单。
中间步骤可用 `--reasoning-effort high`；独立初判、反证终判和资料复核单独使用 `max`。
实际设置以每次请求的 wire 收据为准，推理强度本身不证明研究质量。

因格式错误或中断需要继续时，可给同一冻结资料任务加
`--resume-execution <absolute-private-thesis-execution-directory>`。仅复用连续
完成且实际消息逐字一致的返回；模型、问题或资料不匹配会在发起新请求前拒绝。
原收据保留，新运行的 `budget` 只计新增请求，`reused_calls.prior_budget`
保留被复用运行的用量。服务拆分同一结构的返回时，只合并字段不重叠的片段；
冲突或缺项仍报错，不猜测或改写财务内容。
新请求显式采用JSON输出模式，并在实际消息中声明完整响应结构。已返回但
缺少必要字段的尾部不算完成步骤，继续时从该处重新生成；原始返回与费用保留。
最终判断另检查会计项目重复计入、预测期间、资料审计状态和阈值依据。
若完整运行已保存，但金融内容复核要求重新判断，可在同一冻结任务的
`--resume-execution` 后加 `--reassess-final`。它最多复用截至前瞻提案的十一个输入逐字一致、格式有效的返回，
保留前瞻提案并重新复算，只请求终判和可选复核并保存新Case；若独立初判格式已变化，则从独立初判处重新生成。旧报告保持原样。
它不会自动修复上游金融错误，最终经理仍须回到原始资料核对冲突。

财务口径要求贯穿研究角色，最终报告分别呈现经营表现、盈利质量、现金与
资本配置、估值及价格要求。它要回答经营变化如何传到归母利润和股东价值，
不能仅列数字或检查项。结构完整只证明内容已提交，不能证明金融判断正确。

可以在冻结资料包中追加源自原公告的计算底稿，同时保留原始来源全文。
底稿应标明人工选择或程序提取方式、原表单位/期间/行号、算式与未解决项；
它不是新增独立证据或准入条件。已有 `FinAuditGate.run/replay` 财报组件可
独立协助复算，主流程仍不依赖它。当前已知案例的来源选择与新增计算底稿
由Codex逐案编排，尚未实现任意发行人的自动底稿生成，也不代表独立人工验收。

估值区分历史滚动盈利、供应商预测和条件演算。比如“价格÷假设PE”只给出
该倍数下需要的盈利，倍数未校准时不能称为市场共识或公允价值；还需说明
收入、利润率、非经营损益、税率、归属、股数和汇率如何影响结果。未经验证的
Forward EPS期间、公司Non-GAAP归属、净现金可分配性不能靠模型补齐。

新冻结包版本为 `finresearchops.thesis-sources/v2`，包含 `symbol`、`as_of`、
`identity` 和 `sources`。每条来源包含 `id`、`origin`、`availability_note`、
原样 `content` 及其 UTF-8 `sha256`，以及 `use`：`research` 或 `sensitivity`。
后者只在报告附录中展示，并供后置复核读取；不进入研究者、风险团队、独立初判或反证终判的任何评级请求。
不要把原公告或供应商全部返回误标为情景；含历史计算和自设假设的派生底稿应
逐案拆开并保留来源关系。原始资料字段没有被自动投影或裁剪。
兼容v1输入时所有来源按research处理；程序不会声称识别出了未标注的隐含假设。
可附工具参数和原文哈希。研究日期匹配
不代表当日可得性已经验证，尤其是供应商的当前概况值。

最终评级直接取已验证的结构化`decision.rating`。原生正文评级提取仅作执行记录，
不能因正文提到Hold等其他标签而改写最终评级。若研究经理把唯一的
`valuation_basis_and_gaps`误放在plan内，解析器只逐字移至约定位置；若两个位置
同时有值则拒绝，不选择版本，也不补写财务内容。

主体先保存为独立 Case。`report.md` 解释旧论点与最终判断，`case.json` 保留
来源、各轮结果和实际消息；`review.md` / `review.json` 保存独立复核意见。
新Case使用v10，保留四部分财务分析，并记录精简独立初判、逐信念更新、采用假设和程序事后计算的评级比较；
既有v1/v2仍按原样重开，
不会在重开时补写新判断或覆盖旧报告。
复核未完成、失败或损坏时，主体仍可通过 `read_case` 重开，复核状态单列。
原始模型轨迹、费用与失败输出在私有执行目录保留。
复核读取与 `report.md` 对应的完整文本，包含报告中展示的初稿与更新。
它不是对全部原始轨迹的穷尽审计；完整轮次记录仍供人工进一步核对。
识别到少数错误也不能证明该复核 Agent 已经具有稳定的净收益。

## 独立功能

`investigate-cashflow` 与 FinAuditGate 保留特定财报算术及口径核对。
`research-security` 保留原有财报调查和跨次研究对照；`research-native`
保留受限审核模式及旧 Case 重开。它们不是主入口的必经阶段。

未发布的v3至v9试行格式及原始结果保留在私有开发记录中，不保留为当前公开兼容分支。

章节级财务引用汇总是可选显示项；缺失时不自动补写，也不阻断已有逐条论点/信念引用的报告。四部分财务分析、逐条引用范围、原始输出绑定仍被检查，均不代表金融判断正确。
